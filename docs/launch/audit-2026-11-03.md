# Website audit (3 Nov 2026) — verification, root causes, fixes

Source: `Pahadi_Khatki_Website_Audit_Report.docx` (UI · Security · SEO · Performance). Every finding below was
re-checked against the live hosts (`curl -D -` on 2026-11-02 UTC) and the code before anything was changed.
Items the report missed are in §3. Fix status + evidence is kept in §4 (updated as work lands).

Hosts: production `https://pahadikhatki.in` (coming-soon lock, D-61) · staging `http://staging.pahadikhatki.in`
(full store + admin). **Both are served by the same containers** (`docker-compose.prod.yml` + `docker/nginx/nginx.conf`):
one storefront image, one API, one admin build. The lock is host-aware (`lib/launch-mode.ts`).

## 3. Missed by the report (found during reverse-engineering)

| # | Finding | Severity | Why it matters |
| :-- | :-- | :-- | :-- |
| M-1 | Canonical + sitemap + OG URLs point to `http://localhost:3001` on the live hosts | **High (SEO)** | Google will treat every page as a duplicate of a non-existent host. |
| M-2 | API behind nginx without `TRUST_PROXY=true` ⇒ one shared rate-limit bucket for all visitors | **High (security + availability)** | 5 wrong staff logins from anyone lock the login for everyone; 10 checkouts / 10 min total for the whole store; per-IP OTP limits meaningless. (Opposite risk if `TRUST_PROXY=true` is set but nginx is not the only path — nginx is, ports 4001/5174/3001 are loopback-only.) |
| M-3 | Home + `/products` permanently dynamic (R-21 root cause) | Medium (perf) | No CDN/browser caching, every hit renders; `s-maxage` lost. |
| M-4 | Staging indexable (no `noindex`, allow-all robots, no auth) | Medium (SEO) | Duplicate content + demo products in Google. |
| M-5 | Seller/policy facts can't reach the Docker image (R-1 root cause) | High (launch blocker) | Filling `.env` alone would not fix "Pending". |
| M-6 | Prod lock blocks `/.well-known/*`, `/sitemap.xml` (404) while locked | Low | Fine during lock, must open on launch; `security.txt` needs a pass-through. |
| M-7 | Default nginx catch-all (`server_name _`) 302s raw-IP traffic to staging over HTTP | Low | Leaks the staging host to scanners; should drop (444). |
| M-8 | No idle timeout for admin sessions (R-12) + refresh token valid 30 days on a shared device | Medium | Covered by the new idle rule (ADMIN only). |
| M-9 | No launch-readiness guard: `LAUNCH_MODE=live` can be flipped with Pending legal facts, `http://` site URL, localhost CSP | Medium | A script now blocks it (`scripts/check-launch-readiness.mjs`). |
| M-10 | `nginx` version banner exposed (`Server: nginx/1.31.7`) | Low | `server_tokens off`. |
| M-11 | Decisions log has uncommitted D-62/D-63 (combos, reviews) — reviews are v2; the report's "real reviews" is out of launch scope | Info | Noted, not built (Rules §1.5: no out-of-scope features). |

## 5. Needs the business (cannot be coded)
Fill these in the server `.env` (the values are compiled into the storefront image → `pnpm deploy:storefront`):
`NEXT_PUBLIC_SELLER_LEGAL_NAME`, `NEXT_PUBLIC_SELLER_ADDRESS`, `NEXT_PUBLIC_SELLER_FSSAI_NO`, `NEXT_PUBLIC_SELLER_GSTIN`,
`NEXT_PUBLIC_SELLER_PHONE`, `NEXT_PUBLIC_SELLER_EMAIL`, `NEXT_PUBLIC_SELLER_WHATSAPP`, `NEXT_PUBLIC_SELLER_SUPPORT_HOURS`,
`NEXT_PUBLIC_SELLER_GRIEVANCE_NAME/_DESIGNATION/_EMAIL/_PHONE`, `NEXT_PUBLIC_POLICY_*`, plus the same seller details in
admin → Settings → `seller_details` (invoices). `scripts/check-launch-readiness.mjs` refuses `LAUNCH_MODE=live` until they exist.
Also manual: Google Search Console (sitemap), Google Business Profile (Kangra), securityheaders.com / SSL Labs re-run,
`pnpm db:demo:clear` on production before launch, certbot run for `staging.pahadikhatki.in` (`docs/ops/staging-https.md`).
